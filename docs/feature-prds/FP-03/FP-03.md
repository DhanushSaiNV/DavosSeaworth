## 1. Summary

FP-02 shipped stage 2 of the pipeline as the specced stub: deterministic, emitting the exact §6.3 shape with hardcoded defaults (`domain 'Career'`, `emotion 'determined'`, `overall_conf 0.80`). Tier routing is therefore cosmetic — persona chips, question mode, and auto-adopt fire on placeholder values — and every downstream consumer that reads classification output is running on fake signal.

FP-03 swaps in the real classifier specified by D19 / TECH-SPECS §6: the message is embedded once — the **same `llm.embed` call the pipeline already makes for stage-3 rule retrieval** — and nearest-matched via pgvector against the existing `exemplars` table (§3.3, migration 0006), independently over its three sets: `domain` (16 labels × ~10), `emotion` (6 labels × 8, label list from `config.emotion_labels`), `quit_signal` (labels `quit` + `false_constraint`, 10 each) — ~228 rows total (§6.4). The top match per set gives the label and its confidence; `overall_conf = min(domain_conf, emotion_conf)`; `quit_signal` is a single boolean, true when the quit-set top similarity ≥ 0.75. A turn carrying a check-in energy score forces the emotion label (≤ 3 → `exhausted`, ≥ 8 → `determined`, §6.2). The output block is the unchanged §6.3 contract.

Cost posture: **zero new LLM calls, zero new runtime embed calls, zero new job types.** Classification adds one deterministic RPC round trip per turn. The swap is config-driven (`classifier_mode: 'stub' | 'real'`): FP-03 merges dark (mode `stub`, zero behavior change), seeds and evaluates, then flips to `real`. Rollback is a config flip — no redeploy.

## 2. In Scope / Out of Scope

**In scope**

- Migration 0024: `exemplars.source` column (seed/clear/swap tagging, the rules `source_figure` pattern) + four config keys (`classifier_mode`, `quit_signal_threshold`, `energy_exhausted_max`, `energy_determined_min`)
- Migration 0025: `match_exemplars` RPC — per-`(set_kind, label)` max cosine similarity, hardened (`search_path`), granted like `match_rules`
- Placeholder exemplar module (~228 PLACEHOLDER-DEV items) + `dev-smoke` `seed-exemplars` / `clear-exemplars` actions (embed-at-seed, one batched `llm.embed` — the seed-rules pattern)
- `classifyReal` — drop-in behind the §6.3 contract, stub preserved byte-for-byte as the rollback path; D7 fallback block on internal failure or unseeded sets (stage 2 stays non-fatal per §5.1)
- `runPipeline` mode branch: `[extract ∥ embed]` → classify → persona → retrieve → generate; energy accepted as an optional turn input (no chat-turn caller passes one)
- Dev overrides (`dev_force`) honored in real mode, post-classification
- Golden set (40 items) + eval gate + config-only calibration + archived report
- BG-04 swap drill (data-only replacement proof) + runbook; doc write-backs; acceptance doc

**Out of scope**

- BG-04 approved content itself — parallel track, never blocks mainline
- Check-in energy wiring: `submit-checkin` does not exist yet; §6.1 scopes the energy input to check-in turns, so chat turns pass none and the check-in FP threads the score later
- Downstream consumption of `quit_signal` / domain / emotion (lockdown D21, trust D20, Strike D24) — later FPs
- `band_shift` writing (the §5.4 rider — FP-02 precedent leaves it out; FP-03 only makes the counter's input real)
- Embedding model change / re-embedding migration (D5 frozen `gemini-embedding-001@768`)
- Vector index (HNSW) — unnecessary at ~228 rows; revisit past ~1k
- Hardening the pre-existing `match_rules` `search_path` gap — recorded as known drift, not FP-03's change

## 3. User Stories

1. **As a user** sharing a concrete fitness or relationship problem, I want Davos to recognize the life-domain it belongs to, so the advice draws on the rules written for that domain instead of always defaulting to Career (the stub's fixed answer).
2. **As a user** writing while drained or fired up, I want the emotion in my words recognized, so the persona matches my state instead of always `determined` — and once check-ins land, my energy score should reinforce that reading.
3. **As a user** wavering about quitting or citing fake constraints ("I have no choice"), I want that signal detected from my phrasing, so the anti-quit machinery (later FP) has something true to act on.
4. **As the beta operator** (solo dev, $0), I want exemplar sets swappable as pure data, so BG-04's approved set can land any time without a redeploy or code change.
5. **As the developer**, I want a one-line rollback to the FP-02 stub, so a misbehaving classifier never takes the beta down with it.

## 5. Non-Functional Requirements

| ID | Requirement |
|---|---|
| NFR-1 | **Latency**: real mode adds only the RPC round trip to the turn's critical path (the embed already existed for stage 3) — p95 turn-latency delta vs stub mode ≤ 100 ms |
| NFR-2 | **Cost ($0)**: seed = one batched embed of ~228 texts (adapter-chunked, ≤ ~3 requests), once per seed; eval ≈ 40 embeds + 40 RPCs per run; runtime = zero new provider calls. Verified limits (D5/D18) leave orders of magnitude of headroom |
| NFR-3 | **Determinism**: no LLM in the classify path; identical (text, seeded set) → identical output |
| NFR-4 | **Testability**: golden-set gates (clear-domain ≥ 0.90, energy-override compliance 100%); unit tests for boundaries, override, fallback; FP-02 suite green under both modes |
| NFR-5 | **Security**: exemplar writes service-role only; RPC read-granted like `match_rules`; no client-writable classification inputs |
| NFR-6 | **Auditability**: the classify log line is the calibration and acceptance evidence feed (server-only, never persisted to `messages`) |

| ID | Criterion |
|---|---|

## 8. Risks

| ID | Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|---|
| R-1 | Raw cosine similarities don't center on the 0.75 / 0.55 / 0.40 bands → tier skew (everything auto, or everything fallback) | Medium | High | Golden-set calibration before the flip; bands are the existing `confidence_bands` config (a move is a D4 product change needing a decisions entry); dark-ship means zero user impact until calibrated |
| R-2 | Placeholder exemplar quality is weak until BG-04 lands | High | Medium | Clearly-voiced authoring rules; `classifier_mode` keeps the stub one flip away; BG-04 swap is data-only (AC-8 drill proves it) |
| R-3 | Embeddings are single-provider (Gemini; Groq is generation-only) | Certain (by design) | Medium | Existing FP-02 degrade path already covers embed transport failure (holding reply + `llm_retry` re-runs the embed); monitor degraded rate |
| R-4 | Domain label-string drift (exact strings with slashes — `Mental/Emotional`, `Discipline/Habits`, `Environment/Home`, `Purpose/Legacy`) between exemplars, rules, and the canonical list → silent zero-rule retrieval | Medium | Medium | Labels are data (FR-2); Step 2 verify includes a label-parity check (exemplars vs rules vs §3.3 list); BG-02 memo lands as data |
| R-5 | Forced-emotion confidence semantics are spec-silent (reading: the forced label's own best similarity) — could systematically drag `overall_conf` down on low-energy turns | Medium | Medium | Reading recorded in the plan and written back to TECH-SPEC §6.2; golden-set energy subset measures it; if it skews tiers, the calibration session decides (config-first) |
| R-6 | Seed burns quota | Low | Low | Embed-at-seed is one batched call per seed (~3 requests); no runtime additions; verify-step logs the call count |
| R-7 | Stub/real behavioral divergence beyond the contract (e.g. stage-order latency) | Low | Medium | Contract test + FP-02 suite green under both modes is a step-5 gate; the await-point move is the only orchestration change |
