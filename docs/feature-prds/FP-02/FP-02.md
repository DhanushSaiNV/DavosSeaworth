## 1. Summary

Make Davos talk. A user types a message in the chat thread; `send-message` runs the 5-stage pipeline in one synchronous Edge Function invocation; Davos replies in-character via an anchored-JSON generation call with server-side stripping; the reply renders over Realtime and arrives as an Expo push when the app is backgrounded. Provider failures degrade gracefully (`sync_degrade_reply` + `llm_retry` on the fallback provider). Stage 2 is a deterministic stub classifier; stage 3 runs over a clearly-labeled placeholder rules seed. No memory, no trust, no lockdown, no check-ins — those ride this pipeline later.

## 2. In scope / Out of scope

**IN:**

- Provider adapter (`llm.generate` / `llm.embed`): Gemini 3.5 Flash-Lite primary, Groq fallback, structured output per the FP-01 §13 verification result (JSON mode or the documented degrade path)
- `send-message` Edge Function: auth, user-message insert, 5-stage pipeline, assistant-message insert (service role), push send
- Stage 1: per-turn extraction call, full §4.3 contract (fields extracted but not yet consumed — contract stability over feature scope)
- Stage 2: **stub classifier** — deterministic, emits the exact §6.3 JSON shape; dev override to force any confidence band (explicitly labeled dev-only)
- Stage 3: user-message embedding (`gemini-embedding-001@768` stamp), rule retrieval (top-5 per domain), conflict filter (§5.2)
- Dev-seed: placeholder rules (~8–10, ≥2 domains, including a same-domain aggressive/empathetic pair within 15 priority points to exercise the filter) — clearly labeled placeholders (AGENTS.md §8.4)
- Stage 4: three-tier routing off effective bands (config bands + `persona_stats.band_shift`): High auto-adopt · Medium persona chips + `select-persona` re-run · Low explicit question · <0.40 → General/inquirer (D7)
- Stage 5: generation contract §4.2 (anchored JSON, one bounded parse retry, `malformed_fallback_reply`), server-side stripping of `tactical_analysis`
- Guardrails prompt v1 (D13): persona system prompt + few-shot bad/good exemplar pairs (dev placeholder set, provider-tested on both providers), four route variants (High personas / Medium options / Low question / inquirer fallback)
- `auto_adopt_successes` increment (user reply within 10 min of a High-tier auto-adopt)
- `llm_retry` job handler (fallback-provider re-execution → assistant message + push; dead-letter, never loop)
- Expo push: token registration (`expo-notifications` → `push_tokens` upsert), server send per AI message with collapse key `chat_{userId}`, client-side foreground suppression
- Chat composer enabled; persona chips UI; "Davos is thinking…" indicator; offline queue (local store, `client_sent_at`, ordered retry, server dedupe by client uuid)

**OUT (explicitly — do not build):**

- Real embedding classifier + exemplar sets (FP-03); final rules/exemplar content (owner deliverable)
- Memory extraction, purge, sliding-window aging (§7.6 — later FP)
- Trust/Openness rider accumulation (§5.4 mechanical writes) — deferred: no consumer or test surface until the Oath FP; extraction fields are already in the contract so no stage-1 rework later
- Lockdown / `dialog_state` handling (D21 — no setter exists yet; pipeline hook lands with that FP)
- `user_overrides` decrement path — **owner decision required**: TECH-SPECS defines no override input UI; flagged in §8
- Check-in loop, journal chain, anchor plans, dashboard, onboarding logic, urge machinery
- iOS remote push — see §8 risk 1 (blocked by $0 vs Apple Developer Program; degrades, not dead)

## 3. User stories

1. As a beta user, I can type a message to Davos and receive an in-character, opinionated reply in the thread.
2. As a beta user, when Davos is unsure how to coach me, I see persona chips, pick one, and the reply adopts it.
3. As a beta user, I receive a push notification for Davos's message when the app is backgrounded (Android/Web), and none when I'm reading the chat.
4. As a beta user, messages I send while offline are delivered in order once, when I reconnect.
5. As the owner, when the LLM provider fails, I get an immediate holding reply and the real reply arrives via the retry path.
6. As the owner, I can force each confidence tier via the dev override and verify correct routing end-to-end.

## 5. Non-functional requirements

- $0: no paid service; Expo push service and cron-job.org are free-tier.
- Every invocation completes < 150 s (verified limit); target p50 < 40 s.
- Quota discipline: adapter logs per-provider call counts; a 20-message session must stay inside Gemini 15 RPM / 500 RPD and Groq 30 RPM / 1,000 RPD.
- Deno-compatible dependencies only; secrets only in Edge Function secrets.
- All [SPEC] values read from `config` at runtime, never hardcoded (AGENTS §2).
- Idempotency: `llm_retry` and `send-message` re-delivery must not duplicate assistant messages (job/message idempotency keys).

## 6. Acceptance criteria (all must pass)

- [ ] **AC-1:** Send any message → user row + assistant row appear; `messages.metadata` and `messages.content` contain zero `tactical_analysis` content; Edge Function logs contain it (stripping verified in both directions).
- [ ] **AC-2:** 10-turn conversation shows zero "As an AI…", zero generic-apology filler, in-character tone throughout (qualitative gate, D13; prompt iteration expected — record v1 shortfall notes for the hardening pass).
- [ ] **AC-3:** Dev override → Medium: message carries 2–3 `persona_options`, chips render, tap → `select-persona` → new assistant message in the chosen persona; consumed options reject re-selection.
- [ ] **AC-4:** Dev override → Low: explicit interaction-mode question; <0.40: inquirer-style clarifying question, domain recorded as `General`.
- [ ] **AC-5:** With the seeded conflicting rule pair, retrieval passes exactly one tone group (verified via a debug field or server log of surviving rule ids).
- [ ] **AC-6:** Forced provider failure: immediate `sync_degrade_reply` message + push; `llm_retry` job completes on the fallback provider and the real reply arrives + pushes; with both providers forced dead, the job dead-letters — no infinite loop.
- [ ] **AC-7:** Background the app (Android) → send a message from web → notification arrives (collapse key groups repeats); with chat foregrounded → no notification, message renders via Realtime <2 s.
- [ ] **AC-8:** Airplane mode → send 2 messages → queue locally in order → reconnect → both delivered exactly once each (dedupe verified by row count) → pipeline runs per message.
- [ ] **AC-9:** Reply within 10 min of a High-tier reply → `persona_stats.auto_adopt_successes` +1; reply after 10 min → unchanged.
- [ ] **AC-10:** Timing log across 20 turns: p50 < 40 s, max < 150 s; per-provider call counts within quotas.
- [ ] **AC-11:** Placeholder rules all carry the dev label and are removable in one step; final-content paths untouched.
- [ ] **AC-12:** Doc write-backs in the same change: `messages.client_message_id` in §3.2, §11 registry additions, any new identifiers in GLOSSARY.

## 7. Build order

1. Provider adapter + `config` additions + embedding smoke (768-dim round-trip).
2. Dev-seed rules script + retrieval + conflict filter (testable without UI).
3. Pipeline stages 1–5 as pure functions + guardrails prompt v1 (forced inputs, output inspection).
4. `send-message` wiring: insert, pipeline, assistant write, stripping, push send.
5. Composer UI + thinking indicator + Realtime render (FP-01 subscription reused).
6. Tier routing UI: chips + `select-persona` + dev override surface.
7. Push: token registration + server send + foreground suppression.
8. Sync degrade + `llm_retry` handler.
9. Offline queue + dedupe index.
10. `auto_adopt_successes` write path.
11. AC sweep + doc write-backs.

## 8. Risks

| Risk                                                                                                                                                                        | Mitigation                                                                                                                                                                                                                      |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **iOS remote push requires Apple Developer Program ($99/yr) — violates $0.** Expo Go on iOS does not support remote push; local notifications (check-ins, later) still work | Ship push for Android/Web; iOS degrades to in-app Realtime; escalate to owner as a budget decision before any iOS-dependent feature (interventions, probes, Strikes) is judged "done" — record as a live item in TECH-SPECS §13 |
| Guardrails prompt v1 will not fully break the model's polite habits on first try (D13 trade-off)                                                                            | AC-2 is intentionally qualitative; log shortfalls, iterate prompt within FP-02, unresolved gaps go to the §14 step-11 hardening pass                                                                                            |
| Groq JSON-mode status per FP-01 §13                                                                                                                                         | Degrade path already specced (§4.1); whichever was recorded governs — no new decision needed                                                                                                                                    |
| Sync latency up to ~40 s feels dead                                                                                                                                         | Thinking indicator mandatory (FR-17); if p95 > 60 s in practice, escalate to owner for an async-generation option — do not silently split the pipeline                                                                          |
| Dev iteration burns daily quotas (every manual test = 2+ LLM calls)                                                                                                         | Quota log from the adapter; PLAN should include a stub-provider mode for UI work                                                                                                                                                |
| Edge Function cold starts inflate latency                                                                                                                                   | Measure in AC-10; acceptable at beta scale                                                                                                                                                                                      |
