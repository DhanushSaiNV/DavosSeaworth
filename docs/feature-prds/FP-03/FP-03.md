## 1. Summary

FP-02 shipped stage 2 of the `send-message` pipeline as a **deterministic stub**: it emits the correct §6.3-shaped classification block, honors the dev tier-forcer, and lets the rest of the pipeline run — but it does not actually classify. Tier routing is therefore fake (persona chips, question mode, and auto-adopt fire on stub values, not signal), and downstream consumers (lockdown, trust, Strike) have nothing real to consume.

FP-03 replaces that stub with the **real classifier specified in D19 / TECH-SPECS §6**: an embedding-similarity classifier over pgvector exemplar sets. Each user message is embedded once (`gemini-embedding-001` @ 768 dims, frozen per D18) and compared via cosine similarity against curated exemplar sets:

| Set | Labels | Exemplars per label | Total |
|---|---|---|---|
| Domains | 16 (canonical list: TECH-SPECS §6 / BG-02 memo) | ~10 | ~160 |
| Emotions | 6 (incl. `exhausted`, `determined` — the energy-forced labels) | 8 | 48 |
| Quit | 1 | 10 | 10 |
| False-constraint | 1 | 10 | 10 |
| **Total** | | | **~228** |

Best-matching label per set wins. Energy from stage-1 extraction forces the emotion label (`≤3 → exhausted`, `≥8 → determined`). Confidence composes as `overall_conf = min(domain_conf, emotion_conf)` (D19), which maps through the D4 tier thresholds (High ≥ 0.75 auto-adopt / Medium 0.55–0.74 chips / Low 0.40–0.54 question / < 0.40 inquirer fallback).

Classification itself uses **no LLM generation call** — it is a deterministic nearest-exemplar computation: one embedding request plus one SQL round trip. Marginal cost is $0 within free-tier quotas, latency is bounded and predictable, and identical inputs always produce identical outputs. This is exactly the Adaptive Statistical Weighting posture the PRD amended to specify (statistical, not ML).

The swap is **config-driven** (`classifier.mode: stub | real`): FP-03 merges dark (mode `stub`, zero behavior change), runs the embedding backfill, passes a golden-set eval, then flips to `real`. Rollback is a config flip — no redeploy.

## 2. In Scope / Out of Scope

**In scope**

- `classifier_exemplars` table (pgvector, 768-dim) with RLS locked to service role; source/status tagging (`placeholder` / `bg04_approved` / `calibration`)
- Placeholder exemplar set (~228 items) authored as DRAFT content under `content/classifier-exemplars/` per AGENTS.md §8.4
- Idempotent, batched **embedding backfill job** on the FP-01 jobs system (pg_cron → `jobs` → `job-dispatcher`; backoff, dead-letter, 5-min lease inherited)
- Classification engine module — drop-in replacement for the FP-02 stage-2 stub, §6.3 output contract unchanged
- `classifier.mode` config flag (dark-ship + instant rollback)
- Stage-2 swap in `send-message`; stage 3 (rule retrieval) filters by real domain; stage 4 (persona determination) consumes real conf/tier
- Degradation path: one bounded retry on embedding failure (D13), then a degraded inquirer-fallback result — the pipeline never blocks
- Golden-set eval runner + calibration report (config-tunable thresholds)
- BG-04 hot-swap runbook (data-only replacement of placeholders, zero code change)

**Out of scope**

- BG-04 content itself (approved exemplars) — parallel track, never blocks mainline
- Any change to tier semantics/thresholds (D4), persona determination behavior, or generation
- Lockdown / trust / Strike features — they *consume* classifier output later
- iOS push (open item carried from FP-02, blocked by $0 — tracked separately)
- Model training/tuning of any kind (threshold calibration in config is the only tunable)
- Vector index optimization (unnecessary at ~228 rows; revisit above ~1k exemplars)

## 3. User Stories

1. **As a user** sharing a concrete work problem, I want Davos to recognize the life-domain it belongs to, so the advice draws on the rules written for that domain instead of generic defaults.
2. **As a user** messaging at the end of a draining day (energy 2/10), I want Davos to sense exhaustion even if my words sound neutral, so the persona softens instead of pushing.
3. **As a user** wavering about quitting, I want quit-intent detected from how I phrase things, so Davos doesn't blindly coach me forward (or against) it.
4. **As the beta operator** (solo dev, $0), I want exemplar sets swappable as pure data, so BG-04's approved set can land any time without a redeploy or code change.
5. **As the developer**, I want a one-line rollback to the FP-02 stub, so a misbehaving classifier never takes the beta down with it.

| FR-01 | **Exemplar store**: `classifier_exemplars` with `set_kind ∈ {domain, emotion, quit, false_constraint}`, `label`, `text` (5–400 chars), `source`, `status`, `active`, `embedding vector(768)`, `embedded_at`; unique `(set_kind, label, text)`; RLS enabled with **no policies** (service-role only) | D19; TECH-SPECS SQL Schemas |
| FR-02 | **Labels are data**: the engine reads label sets from the table at runtime; no hardcoded domain/emotion lists in code | TECH-SPECS §6; BG-02 alignment |

| FR-04 | **Backfill job**: async job type `exemplar_embed` on the FP-01 jobs system; idempotent (`embedded_at` guard); batched (≤ 50/run); partial failure retries with backoff, repeat failure dead-letters | D2; D18 |

| FR-07 | **Energy override**: `energy ≤ 3 → emotion = exhausted`; `energy ≥ 8 → emotion = determined`; forced-label confidence = its best exemplar similarity, floored by config (default 0.75) so tier routing cannot collapse on a forced label | D19; open reconciliation vs TECH-SPECS §6 (see PLAN Appendix B) |
| FR-08 | **Confidence composition**: `overall_conf = min(domain_conf, emotion_conf)` | D19 |
| FR-09 | **Tier suggestion**: ≥ 0.75 High / 0.55–0.74 Medium / 0.40–0.54 Low / < 0.40 inquirer fallback; thresholds read from the config registry (tunable without redeploy) | D4; TECH-SPECS Config Registry |
| FR-10 | **Flags**: emit `quit_conf` / `false_constraint_conf`; flag when ≥ config cutoff (default 0.75); no downstream behavior in FP-03 | D19; future lockdown/Strike |

| FR-12 | **Mode flag**: `classifier.mode ∈ {stub, real}` in config; stage 2 branches on it; merges default `stub` | FP-02 patterns; D2 |
| FR-13 | **Degradation**: exactly one bounded retry on embedding failure, then a degraded result (`overall_conf = 0` → inquirer fallback, `degraded: true`); `send-message` always completes to generation; no retry loops | D13 |
| FR-14 | **Dev tier-forcer**: preserved from FP-02, honored in non-prod only, before tier mapping | FP-02 |

## 5. Non-Functional Requirements

| ID | Requirement |
|---|---|
| NFR-01 | **Latency**: stage-2 adds p95 ≤ 1.5 s (one embedding RTT + one SQL round trip); must fit the stage budget in TECH-SPECS Pipeline Contracts |
| NFR-02 | **Cost**: $0 — backfill is one-time (~228 texts, batched); runtime is one embedding per message; 5 beta users sit far inside free quotas |
| NFR-03 | **Determinism**: identical (message, active exemplar set, model) → identical output; no LLM in the classification path |
| NFR-04 | **Provider**: embeddings are Gemini-only (frozen per D18); the Groq fallback covers chat models, **not** embeddings — on embed failure, degrade, never fail over |
| NFR-05 | **Storage**: ~228 × 768 floats ≈ < 1 MB — trivial |
| NFR-06 | **Testability**: golden set ≥ 90% domain accuracy on clear cases; 100% energy-override compliance; contract test green |
| NFR-07 | **Auditability**: per-label similarities persisted server-side with each classification (server-only, per the D13 `tactical_analysis` pattern) |
| NFR-08 | **Security**: exemplar table invisible to `anon`/`authenticated` (RLS, no policies); content files carry DRAFT status until BG-04 approves |

## 6. Acceptance Criteria

| ID | Criterion |
|---|---|
| AC-01 | With `mode=real`, a clear domain-X message classifies as domain X with conf ≥ 0.75 → High tier → auto-adopt path; stage 3 retrieves domain-X rules; §6.3 contract test passes unchanged |
| AC-02 | Boundary fixtures produce all four tiers exactly at the 0.75 / 0.55 / 0.40 edges (unit-level, synthetic similarities) |
| AC-03 | Energy ≤ 3 → `exhausted` regardless of similarity; ≥ 8 → `determined`; 100% of golden-set override cases comply |
| AC-04 | Quit-phrased fixture sets `quit_flag = true` at ≥ cutoff; a neutral fixture does not |
| AC-05 | Embedding provider in fail-mode → one retry → degraded result with `suggested_tier = inquirer`; `send-message` still returns a generated reply; degraded count increments |
| AC-06 | Flipping `classifier.mode` back to `stub` restores FP-02 behavior with no redeploy (FP-02 test suite green) |
| AC-07 | One backfill enqueued → all seeded exemplars embedded (228/228); a second run is a no-op; a failing batch retries with backoff and dead-letters per the jobs system |
| AC-08 | Upserting a mini approved set (2 labels × 2 items) and deactivating placeholders changes classification with no code change or redeploy |
| AC-09 | Golden-set clear-case domain accuracy ≥ 90%; report archived under `docs/eval-reports/` |
| AC-10 | Dev tier-forcer still forces each of the four tiers in dev |

## 8. Risks

| ID | Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|---|
| R-01 | Raw cosine similarities don't center on the 0.75/0.55/0.40 thresholds → tier skew (everything High, or everything inquirer) | Medium | High | Thresholds live in config; golden-set calibration session before the flip; ship-dark means no user impact until calibrated |
| R-02 | Placeholder exemplar quality is weak until BG-04 lands | High | Medium | Placeholders written to be clearly-voiced per label; mode flag keeps stub one flip away; BG-04 swap is data-only |
| R-03 | Embeddings are single-provider (Gemini) — no Groq equivalent | Certain (by design) | Medium | Degraded path is safe (inquirer fallback never blocks chat); monitor degraded rate; D13 forbids retry loops |
| R-04 | Backfill loops and burns quota | Low | Medium | `embedded_at` idempotency guard; batch cap; jobs-system backoff + dead-letter |
| R-05 | Exemplar labels drift from the BG-02 domain enum | Medium | Low | Labels are data (FR-02); post-BG-02 validation query flags orphans |
| R-06 | Embedding settings mismatch (exemplars vs messages) silently corrupts similarity | Low | High | FR-05 is a named requirement + a dedicated test asserting both paths use one shared config object |
| R-07 | Embedding free-tier quota smaller than assumed | Low | Medium | Verify in AI Studio console during Phase 3; batched backfill minimizes request count; 5 users trivial at runtime |
